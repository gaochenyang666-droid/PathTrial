## Что такое PathTrial и кому он пригодится?

Почему сайт не открывается, хотя сервер отвечает на Ping? Почему TCP-соединение с VPS устанавливается, но прокси не работает? Почему IPv6 работает, а IPv4 — очень медленно?

**PathTrial — бесплатная утилита с открытым исходным кодом для командной строки.** Она по отдельности проверяет DNS, TCP, TLS, HTTP и другие компоненты соединения, сохраняет фактические результаты и формирует отчёт, который можно изучить самостоятельно или приложить к обращению в поддержку.

- **Кому подходит:** пользователям, которые хотят разобраться с подключением; администраторам VPS, домашних серверов и прокси; тем, кто сравнивает IPv4 и IPv6.
- **Для установки Rust не нужен:** для поддерживаемых платформ уже есть готовые исполняемые файлы. Не требуется аккаунт или отправка данных в облако.
- **Не меняет настройки:** программа не перенастраивает DNS, маршруты, межсетевой экран или системный прокси.
- **Не исправляет сеть автоматически:** она показывает, что удалось наблюдать, и отдельно указывает, какие причины пока не доказаны.
- **Работает в терминале:** графического интерфейса пока нет. Проверяйте только собственные системы или ресурсы, на тестирование которых у вас есть разрешение.

Например, если TCP-соединение устанавливается, но TLS-рукопожатие завершается ошибкой, PathTrial покажет результаты этих этапов отдельно, не называя всё соединение исправным.

### Установка без Rust (рекомендуется)

Откройте приложение **«Терминал»** на macOS или терминал в Linux. Выполняйте команды по очереди:

~~~sh
# Скачайте установочный скрипт из официального GitHub Release

# Просмотрите содержимое перед выполнением
less pathtrial-install.sh

# Установите программу: архив будет проверен по SHA-256
sh pathtrial-install.sh
~~~

Программа устанавливается в **~/.local/bin/pathtrial**, права sudo не нужны.

Для тех, кто уже проверил скрипт и доверяет ему, есть однострочный вариант:

~~~sh
curl -fsSL https://github.com/gaochenyang666-droid/PathTrial/releases/download/v1.3.0-rc.1/install.sh | sh
~~~

**Важно:** запуск скачанного скрипта напрямую связан с риском безопасности. Проверка SHA-256 подтверждает содержимое загруженного архива, но сама по себе не гарантирует безопасность установочного скрипта.

**Не хотите выполнять скрипт?** Скачайте нужный архив из таблицы выше, распакуйте его, найдите исполняемый файл **pathtrial** и откройте терминал в его каталоге. Запустите **./pathtrial --version**. При необходимости переместите файл в каталог из PATH.

## Шаг 3. Проведите первую проверку

Начните с короткой проверки тестового сайта:

~~~sh
pathtrial scan example.com --profile web --rounds 5 --redact-ips
~~~

Если команда **pathtrial** не находится, замените её на **~/.local/bin/pathtrial**.

Параметры:

- **example.com** — домен для проверки; замените его на ресурс, который имеете право тестировать.
- **--profile web** — профиль для веб-соединений и TLS.
- **--rounds 5** — пять попыток для каждой применимой семьи IP-адресов.
- **--redact-ips** — маскировка IP-адресов в отчёте для последующей передачи.

Обычный анализ проходит пять последовательных этапов: **системная информация → DNS → TCP/TLS → сравнение IPv4/IPv6 → отчёт**.

**Успешный TLS-обмен ещё не означает, что сервер возвращает рабочую веб-страницу.** Чтобы проверить реальный HTTP-ответ, выполните:

~~~sh
pathtrial http https://example.com/
~~~

Чтобы проверить SSH-порт собственного VPS:

~~~sh
pathtrial scan YOUR_VPS_IP --profile ssh --port 22 --rounds 5 --redact-ips
~~~

Вместо **YOUR_VPS_IP** подставьте адрес своего сервера. Не добавляйте угловые скобки.

## Шаг 4. Разберитесь в результатах и отчётах

| Статус | Значение |
| --- | --- |
| **PASS** | Конкретная проверка соответствует заданному условию |
| **WARN** | Получен результат, но обнаружена аномалия |
| **FAIL** | Конкретная проверка не соответствует заданному условию |
| **SKIP** | Проверка неприменима или её не удалось провести; **это не успех** |
| **INCONCLUSIVE** | Проверка выполнена, но данных недостаточно для достоверного вывода |

По умолчанию команда **scan** сохраняет два файла в **текущем рабочем каталоге**:

- `pathtrial-report-<run_id>.md` — читаемый отчёт Markdown для человека или техподдержки.
- `pathtrial-report-<run_id>.json` — структурированные данные для анализа и сообщений об ошибках.

Чтобы найти Markdown-отчёт:

~~~sh
ls pathtrial-report-*.md
~~~

Чтобы вывести Markdown прямо в терминал без сохранения файлов:

~~~sh
pathtrial scan example.com --format markdown --no-files
~~~

Для JSON используйте **--format json**. В отчёте указаны результаты, подтверждающие их измерения и **причины, которые ещё не доказаны**. По одной неудачной проверке нельзя достоверно определить провайдера, виновника фильтрации или точный сетевой узел, теряющий пакеты.

Коды завершения: **0** — нет WARN/FAIL; **1** — ошибка самой программы; **2** — есть WARN/FAIL; **3** — недостаточно данных для вывода. Код завершения не является оценкой исправности всего интернета.

## Шаг 5. Выберите нужную проверку

Для начала достаточно команд **scan** и **http**. При конкретных проблемах используйте следующие примеры:

| Что проверить | Команда |
| --- | --- |
| Сравнить ответы DNS-серверов | pathtrial dns example.com --server 223.5.5.5 |
| Ping и задержку | pathtrial ping 1.1.1.1 --count 5 |
| Маршрут и промежуточные узлы | pathtrial trace example.com --max-hops 15 |
| TCP/SSH своего VPS | pathtrial scan YOUR_VPS_IP --port 22 --profile ssh |
| Ответ HTTP 200 | pathtrial http https://example.com/ --expect-status 200 |
| Настоящее QUIC-рукопожатие | pathtrial quic example.com --port 443 --alpn h3 |
| Настоящий запрос HTTP/3 | pathtrial http3 https://example.com |
| Сравнить два отчёта | pathtrial compare old.json new.json |

**О QUIC/HTTP3:** сервер должен поддерживать нужный протокол, а UDP-маршрут — работать. Сам по себе тайм-аут рукопожатия не доказывает отсутствие HTTP/3 на сервере.

### Если вы используете SOCKS5 или HTTP CONNECT

Предположим, у вас уже запущен локальный SOCKS5-прокси, который слушает порт 1080:

~~~sh
pathtrial proxy https://example.com/ --proxy socks5://127.0.0.1:1080
~~~

Сравнить прямой путь и путь через прокси:

~~~sh
pathtrial proxy https://example.com/ --proxy socks5://127.0.0.1:1080 --compare-direct
~~~

Для HTTP CONNECT укажите адрес вида **http://127.0.0.1:8080**. В текущей бета-версии не поддерживается аутентификация прокси по имени пользователя и паролю. Успешный запрос через прокси не доказывает его долгосрочную стабильность.

### Настоящий UDP Echo: два окна терминала

**Терминал A:** запустите временный сервер на локальном адресе:

~~~sh
pathtrial endpoint --udp-echo --bind 127.0.0.1:39001
~~~

**Терминал B:** запустите клиентскую проверку:

~~~sh
pathtrial udp --target 127.0.0.1:39001 --mode echo
~~~

Чтобы остановить сервер, нажмите **Ctrl+C** в терминале A.

Так проверяется только **локальная петля (loopback)**. Для проверки удалённого VPS на нём должен работать совместимый Echo-сервер, а у вас должно быть разрешение на проверку. **UDP Echo не является проверкой QUIC или Hysteria2.**

### Сбор данных с двух сторон (для опытных пользователей)

Для знакомства с функцией можно использовать один компьютер и два терминала:

~~~sh
# Терминал A: серверная сторона
pathtrial collect --role server --task-id demo --listen 127.0.0.1:39001 --max-seconds 30 --output server.json

# Терминал B: запустите, пока терминал A ещё слушает
pathtrial collect --role client --task-id demo --target 127.0.0.1:39001 --rounds 5 --output client.json

# Когда обе стороны закончат сбор данных
pathtrial correlate client.json server.json
~~~

Функция сопоставляет **события TCP-соединений**, а не дампы пакетов. Без захвата пакетов и синхронизации времени нельзя определить конкретное устройство, на котором произошло исчезновение трафика.

## Поддерживаемые платформы и известные ограничения

- **Поддерживаются:** macOS Apple Silicon, macOS Intel и Linux x86_64. Для них выполнены сборка и тестирование на соответствующих CI-платформах.
- **Пока нет:** Windows, графического интерфейса, автоматического исправления сети, автоматического захвата пакетов и определения точного оборудования, на котором теряются пакеты.
- **Fake-IP / TUN:** локальный прокси может подменять DNS и изменять маршрут «прямого» подключения. PathTrial отмечает случаи, когда результаты потенциально вводят в заблуждение.
- **ICMP и UDP:** неудачный Ping не означает, что TCP недоступен; ICMP Port Unreachable не является успешным ответом UDP Echo.
- **HTTP/3:** реальные запросы прошли проверку на контролируемом локальном сервере, но конкретный внешний маршрут UDP 443 может завершаться по тайм-ауту.
- **Осторожно, тестовая версия:** не используйте её как единственный источник решений при мониторинге критически важных производственных систем.

**О версии исходного кода:** скачиваемый исполняемый файл соответствует [тегу v1.3.0-rc.1](https://github.com/gaochenyang666-droid/PathTrial/tree/v1.3.0-rc.1). Ветка **main** может временно отставать от этого выпуска. История разработки расширенных функций находится в [Milestone C PR #1](https://github.com/gaochenyang666-droid/PathTrial/pull/1).

**О языках:** переведена **документация README**, а не вся программа. Вывод команд и сформированные отчёты пока не полностью доступны на русском, английском или испанском.
