看清网络故障发生在哪一层。

PathTrial 将 DNS、TCP、TLS、HTTP、UDP、QUIC 和 HTTP/3 检查分层执行，用真实测量证据解释网站打不开、VPS 端口异常、代理连接失败及 IPv4/IPv6 差异。

Open-source network diagnostics CLI with local MCP integrations for Codex and Claude Code.

为真实的网络排障场景而设计

把“连不上”拆解成可以验证的具体步骤，而不是依赖一次 Ping 或猜测运营商行为。

网站与 DNS 故障

单独观察域名解析、TCP 建连、TLS 握手和 HTTP 响应，区分传输连接异常与应用层问题。

VPS、端口和代理排障

检查网络可达性、SOCKS5 / HTTP CONNECT 代理链路与 UDP Echo、QUIC、HTTP/3 的不同协议行为。

IPv4 / IPv6 对照

用相同目标、端口、轮次和超时比较双栈连通性和延迟，避免从不一致的测试设置得出错误结论。

CLI 直接运行；无需 AI 账号

在自己的 Mac 或 Linux 机器上执行测试。无需云端账号、无后台服务，不会自动修改系统 DNS、代理、路由或防火墙。

诊断结果包含 PASS、WARN、FAIL、SKIP、INCONCLUSIVE，并能导出带 probe ID 的 JSON 报告。

连接 Codex 和 Claude Code

同一 Rust 诊断引擎通过本地 Model Context Protocol（MCP）提供 9 个工具，用于能力检查、授权探测、报告解释与证据引用。

OpenAI Codex 插件

从 GitHub 默认分支添加 Marketplace，安装 PathTrial 插件并检查本地 MCP 连接。

codex plugin marketplace add \
  gaochenyang666-droid/PathTrial
codex plugin add pathtrial@pathtrial

Claude Code 插件

通过 Claude Code 自带的插件命令添加 Marketplace，安装插件后使用 /mcp 检查工具。

# 在 Claude Code 会话内输入
/plugin marketplace add gaochenyang666-droid/PathTrial
/plugin install pathtrial@pathtrial
安全默认设置：网络目标必须明确授权。MCP 默认拒绝所有网络探测；解释和比较已有报告不需要网络目标授权。阅读 MCP 安装及授权指南。

常见问题

PathTrial 和 ping、curl 有什么不同？

PathTrial 不只检查单一协议；它按 DNS、TCP、TLS、HTTP、UDP、QUIC 等阶段记录证据，并明确区分无法确认的原因。单次网络失败不等于准确的根因定位。

安装 PathTrial 是否需要 Rust？

macOS ARM64、macOS Intel、Linux x86_64 用户可以直接下载 v1.4.0-rc.1 预编译版本，不需要 Rust。源码编译才需要 Rust 工具链。

是否会主动探测未授权设备？

本地 MCP 网络探测默认拒绝，必须显式授权目标。请仅测量你有权限访问的系统，分享诊断报告前移除 IP、令牌、代理凭据等敏感内容。
