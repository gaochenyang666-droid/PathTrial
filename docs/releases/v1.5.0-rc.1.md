# PathTrial v1.5.0-rc.1 — Guided network diagnosis

This is a **release candidate**, not a stable release. PathTrial is a standalone, open-source Rust CLI for macOS and Linux with a local MCP server for Codex and Claude Code.

## Highlights

- New `pathtrial diagnose` entry point with 11 scenarios: `web`, `vps`, `latency`, `proxy`, `local`, `dns`, `tcp`, `tls`, `http`, `dual-stack`, and `udp-quic`.
- Evidence-grounded diagnosis across ten common network problem categories. Reports separate observed facts from possible causes, unproven causes, and recommended next checks; evidence references use `<source>:<probe_id>`.
- Latency statistics (TCP P50/P95/max), independent ICMP loss/jitter reporting, HTTP 4xx/5xx interpretation, and read-only local network interface / route / DHCP / Wi-Fi facts where available.
- **10 MCP tools** with the new `pathtrial_diagnose`. Existing startup target allowlist and default-deny rules remain in force.
- `pathtrial_explain_report` supports scan, probe, and guided diagnose report objects, validates real evidence references, and keeps diagnostic uncertainty visible.
- Subprocess deadlines, cancellation and cleanup, TCP task payload reassembly, and HTTP Host/SNI behavior received further hardening and regression coverage.

## Install

Choose the correct archive for macOS Apple Silicon, macOS Intel, or Linux x86_64 from this Release's assets. Verify its accompanying `.sha256` file before installing. `install.sh` installs to `~/.local/bin` by default without sudo.

Try `pathtrial --version`, `pathtrial diagnose --scenario local`, or `pathtrial diagnose --scenario web example.com --format summary` for targets you own or are authorized to test.

To use the MCP plugin, install the PathTrial executable first and ensure the Codex or Claude Code MCP configuration invokes the matching `1.5.0-rc.1` binary. MCP network targets are denied by default until explicitly allowed.

## Known limitations

- A reported cause may be a hypothesis, not a proven root cause. ICMP loss cannot establish business-traffic loss or locate a responsible hop.
- Wi-Fi / DHCP observability is operating-system dependent and may be `SKIP` or `INCONCLUSIVE`.
- Real external dual-stack, UDP/QUIC and HTTP/3 reachability depends on the test network; a missing server or blocked local path does not by itself prove ISP filtering.
- Windows and Linux ARM64 binaries, a GUI and automatic repair are not provided.
